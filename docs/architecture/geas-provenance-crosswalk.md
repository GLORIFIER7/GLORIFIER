# GEAS provenance crosswalk (proposal)

Status: **recommendation / analysis only**. The W3C PROV-O source is registered as `discovery-only`; this document does not assert that GEAS emits PROV records, that a runtime conforms to PROV-O, or that provenance proves semantic truth.

## Authoritative source

- Registry ID: `w3c-prov-o`
- Specification: [W3C PROV-O Recommendation](https://www.w3.org/TR/prov-o/)
- Scope: interoperable representation of provenance entities, activities, agents, and their relationships.

## Proposed mapping

| W3C PROV concept | GEAS evidence concept | Required linkage | Limitation |
| --- | --- | --- | --- |
| `prov:Entity` | Source snapshot, exact excerpt, state snapshot, test result, build artifact | Stable evidence ID, SHA-256 content/snapshot hash, source or artifact reference | A hash binds bytes to a record; it does not authenticate origin or prove truth. |
| `prov:Activity` | Retrieval, normalization, human claim review, five-state reconciliation, test/build run, deployment observation | Activity/run ID, start/end or observation time, inputs and outputs | A workflow result proves only the activity reported by that workflow. |
| `prov:Agent` | Human reviewer, CI workflow actor, provider/service identity | Stable actor identifier and authentication evidence where applicable | A reviewer string alone is not authenticated identity. |
| `prov:used` / `prov:wasGeneratedBy` | Input evidence consumed and output evidence generated by a scan/review/test | Explicit input/output references and activity ID | Do not infer lineage from timestamps or matching keywords. |
| `prov:wasDerivedFrom` | Architecture analysis derived from an exact source snapshot or prior evidence record | Parent evidence IDs plus content hashes | Derived analysis remains analysis unless claim-level review and independent verification are recorded. |
| `prov:wasAssociatedWith` / `prov:wasAttributedTo` | Reviewer or execution identity associated with a decision or artifact | Actor reference plus authorization/authentication evidence | Attribution is not equivalent to authorization or endorsement. |

## Acceptance criteria before promotion

1. Keep `source-available` and `content-matched` classified as analysis.
2. Bind claim review to a registered source ID, exact canonical URL, registry version, allowed claim type, source snapshot hash, and exact supporting excerpt; the observed URL must resolve to the same registered resource (origin, path, and query; trailing-slash normalization only), not merely the same host.
3. Bind every architecture state independently to its own canonical snapshot hash, evidence references, observation time, and expiry.
4. Preserve `UNKNOWN` when evidence is missing, stale, contradictory, or not authenticated.
5. Record workflow run IDs and artifact digests for test/build provenance; do not infer live deployment or production health from CI.
6. Add deterministic tests for broken, missing, duplicated, or mismatched provenance links before treating the crosswalk as implemented.
